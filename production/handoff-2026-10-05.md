## 已做的决定 + 为什么（不要重新讨论）
**引擎 = UE5。** 三条理由叠加：① 用户用过 UE ② 用户 **C++ 最熟** → 逐格模拟写在 C++ 里就是原生速度，**性能瓶颈直接消失** ③ 美术是纯色格子（色块点阵），恰好绕开 UE 最弱的 Paper2D 素材管线。

被否掉的替代：
- **Godot 4** —— 2D 最强、迭代最快，但用户零经验，且逐格模拟必须自己搭 compute shader / GDExtension
- **Unity 6.3** —— Burst/Jobs 天生适合逐格模拟，但用户两边都不最熟

**关键数字**：256×256 = 65,536 格，60fps → 每秒约 390 万次更新；512×512 = 26 万格 → 约 1570 万次/秒。
GDScript 做不了（约 10–60ms/帧）；C++ 里这是免费的事。

**架构约定（重要）**：把"要反复试的东西"做成**数据驱动** —— 规则表、物质反应表、参数全放数据文件 / 蓝图可编辑变量。
这样调规则**不用重编译**，把 UE 的迭代税压到接近零；只有改内核逻辑才需要编译。

**模板选择 = Blank + C++**。不用俯视角/第三人称模板：它们的弹簧臂相机 + Character + Enhanced Input 映射全是"要拆的东西"；侧视角是 2.5D 平台跳跃的架子。
Starter Content 关 · Desktop · Scalable · Raytracing 关。

## UE MCP（Unreal MCP）已配好并验证通过 — 2026-10-05

**它是什么**：UE 5.8 自带的实验插件 `ModelContextProtocol`（`.uplugin` 里 `FriendlyName: "Unreal MCP"`，

⚠️ 别和 `MCPClientToolset` 搞混 —— 那个是**反方向**（让 UE 去连别人的服务器）。

**位置**：`E:\UE_5.8\Engine\Plugins\Experimental\ModelContextProtocol\`

**服务端参数**（源码实读，勿猜）：
- 传输：**Streamable HTTP**（POST=JSON-RPC、GET=SSE、DELETE=结束会话；`Mcp-Session-Id` 头管会话）
- 默认端口 **8000** · 路径 **`/mcp`** · 服务名 `unreal-mcp` · MCP 规范 2025-11-25

   - 想免手输 → 给编辑器快捷方式加 `-ExecCmds="ModelContextProtocol.StartServer"`
3. DSH 侧已配好，工具以 `mcp__unreal__*` 出现：`list_toolsets` / `describe_toolset` / `call_tool`
   - 调工具集里的工具要用 `toolset_name`（如 `EditorToolset.EditorAppToolset`）+ **不带前缀**的 `tool_name`

**DSH 配置位置**（本会话的 MCP 配置层）：
`C:\Users\14665\.dsh\profiles\web\cordis.patch.yml` → 新增 `mcp-unreal` 条目

reconnect 放宽到近乎无限重试，因为编辑器经常关着）。
注：patch 层新增行**必须用 `insert:` 列表**，裸条目只会被当作"按 id 覆盖已有行"。
